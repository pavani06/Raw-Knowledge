## Key Takeaways

- **Scale makes evals non-negotiable** — [[entities/claggent|Claggent]] (research agent, launched 2023) runs 300M+ runs/month; [[entities/sculptor|Sculptor]] (GTM engineering agent) receives 100k+ messages/week and is now one of the primary ways users interact with [[entities/clay|Clay]]. Both are past the threshold where anyone could read every trace or talk to every customer ([[concepts/agent-evals]]).
- **A good eval suite unlocks agentic development** — with trustworthy evals you can let Claude Code / Codex / Devin-class coding agents make prompt changes for you, knowing nothing reaches production unless the suite passes ([[concepts/eval-driven-development]]).
- **Meet developers where they are** — local evals run as a plain CLI suite: cheap, fast, no sandbox or VFS; CI/staging runs the same harness as close to production as possible; every run is persisted and versioned in LangSmith even when executed locally; new product areas bring their own evaluators (their own LLM judges) into a plug-and-play harness ([[concepts/agent-evals]]).
- **Cover the whole eval matrix, a few things per quadrant** — deterministic/offline (goldens, structured checks, trajectory assertions); offline/non-deterministic (LLM-as-judge); simulated-user multi-turn; deterministic/online (latency, cost, users leaving chat, getting stuck, rage quitting); online/non-deterministic (NPS-style satisfaction, perceived evals, bulk trace analysis) ([[concepts/eval-coverage-matrix]]).
- **Deterministic multi-turn evals beat simulated users** — an agent playing the user (seeded with past-trace examples) was too noisy: "another agent you had to manage and keep up to date and also have evals for"; hard-coded user turns were the most useful variant in practice ([[concepts/eval-coverage-matrix]]).
- **The production→offline feedback arrow is the hardest part** — eval/production drift is an unsolved problem: data drift (production use cases ≠ what the team tested), judge drift (every model family has internal biases; hill-climbing on one judge overfits it), eval-set overfitting (prompts start mirroring a small set). Mitigations: examples pulled from online evaluators, customer support tickets as high-signal feedback, human-annotated goldens to detect judging drift, use-case classifiers tagging eval coverage against production ([[concepts/production-to-offline-feedback-loop]]).
- **One tool surface for internal and external agents** — everything doable in the UI is exposed via CLI and public API, and Sculptor uses exactly those same tools; failures in tool invocations and trajectories become user signal to improve the harness or the tools themselves, improving quality for everyone including external agents ([[concepts/tool-unification-flywheel]]).
- **An agent-first data foundation** — moving to a data-lake architecture that unifies first-party + third-party data, LangSmith traces, Snowflake analytics, Postgres, and ClickHouse into one platform with agents as the first-class user: guardrails up front, safe shadow builds deployed to S3, serving/dev compute separation, heavy investment in agent skills and CLI, and hour-long agent-driven data-model builds over Athena — enabled by the frontier-model step change that fits ~10k examples in context ([[concepts/agent-first-data-foundation]]).

## Connections

- The [[concepts/eval-coverage-matrix]] adds a second axis to the vault's three-tier grader stack: the tiers in [[concepts/agent-evals]] (deterministic → judge → behavioral) describe *how* you grade; the matrix crosses that with *where* (offline vs online), making [[concepts/continuous-evaluation]] a cell of the grid rather than a separate idea.
- Goldens "work great for really simple things" but break under keyword/node reordering — a concrete failure mode compounding [[concepts/golden-dataset]]: noisy evals don't just fail, they get ignored, which is why Clay moved to structured checks over query fragments (see [[concepts/trajectory-evaluation]]).
- Judge drift extends the [[concepts/llm-as-judge]] bias taxonomy (verbosity, authority, self-enhancement) with a temporal dimension: biases compound as you hill-climb on one judge — the drift-shaped cousin of [[concepts/reward-hacking]].
- The [[concepts/tool-unification-flywheel]] is the tool-surface sibling of [[concepts/data-flywheel]]: failure signal compounds into shared tool quality, the same way production failures compound into eval data. Standardized tool surfaces for external agents parallel what [[entities/model-context-protocol|MCP]] does for agent-tool integration.
- The [[concepts/agent-first-data-foundation]] extends [[concepts/data-foundation]] (Databricks' question-data vs tracking-data pillar) from "data agents query" to "data agents operate": shadow builds, separated compute, agent skills — and it operationalizes [[concepts/agent-tracing]] by folding LangSmith traces into the same lake as Snowflake/Postgres/ClickHouse data.
- Clay letting coding agents make prompt changes under eval protection is [[concepts/eval-driven-development]] closing toward [[concepts/closed-loop-evaluation]].
